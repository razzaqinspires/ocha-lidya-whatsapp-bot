## Interpretation and limits

- A blank/undeclared permission property does **not** mean public access. The dispatcher, `src/core/plugin-execution.js`, identity checks, command-specific handler logic, chat scope, rental tenant policy, cooldown and anti-spam gates remain authoritative.
- `menu: false` hides a command from the user-facing `.menu` inventory; it does not by itself mean the plugin is unloaded. In this snapshot `.features` is explicitly hidden.
- Aliases resolve through the same plugin registry as canonical names. Runtime menu generation suppresses alias collisions in favor of canonical names, but the source collision check above found none.
- ACIE-generated commands are dynamic. The ZIP does not include the runtime `generated-commands/index.json` and provider/command runtime registries, so no generated command is counted as active or included in this static inventory.
- Prefix is configurable. The source menu renderer uses the configured prefix and canonical registry; do not hard-code `.` as the only prefix.

## Non-plugin Master Console syntax

`src/master/dispatcher.js` separately recognizes `>>>`, `>>`, `=>`, `>`, and `$`. Both `>` and `=>` map to JavaScript eval; `$` maps to CLI shell; `>>` maps to Python; `>>>` maps to Go. These are not plugin aliases. Runtime flags are independently controlled, and the parser/dispatcher additionally requires a verified owner. JavaScript `vm` is explicitly not a security boundary; these runners must remain owner-only and opt-in.

## Private runtime command boundary

`.test` (`testmsg`, `messagetest`) is supplied only by `@razzaqventures/ocha-private-runtime`. It is not counted among the 46 public plugin descriptors and does not appear in public-compatible mode. The private loader accepts it only when the package passes the serializer/helper/fake-reply contract, the plugin declares both `ownerOnly: true` and `privateOnly: true`, and its canonical name and aliases do not collide with the public or ACIE virtual registry. The live registry must still be checked with `.commandaudit scan` after package activation.
